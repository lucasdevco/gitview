# Spec：Sourcetree 风格 Git 工作台（首批功能）

Status: resolved

相关决策：[ADR-0001 从只读分析工具演进为读写 Git 工作台](../../docs/adr/0001-read-write-git-workbench.md)
界面原型：`/prototype/workbench` 路由（内存假数据），已对照 Sourcetree 截图校准（截图在本地 `docs/prototype/sourcetree/`，不入库）。

## Problem Statement

我想用一个 Sourcetree 那样的可视化 Git 客户端管理本地仓库：看提交图、看每个提交改了什么、暂存和提交改动、切分支、拉取推送。但 Sourcetree 是桌面应用，而 gitview 目前只是一个只读的历史分析工具，既不能操作仓库，界面也是分析报表而不是工作台。

我需要的是：在浏览器里打开一个本地服务，就能完成日常的 Git 工作流，行为和命令行 `git` 一致（同样的配置、hooks、凭据），并且能看到每个操作实际执行了什么 git 命令。

## Solution

把 gitview 重写为 Sourcetree 风格的网页版 Git 工作台。启动 `gitview` 后在浏览器中打开工作台，界面结构与原型一致：

- 标题栏：仓库名，右侧操作按钮：提交、拉取、推送、抓取、分支、合并、贮藏（显示远程服务器、在 Finder 中显示、设置为占位）。提交、拉取、推送按钮显示数字角标。
- 侧边栏：WORKSPACE（文件状态 / 历史 / 搜索）、分支（按 `/` 分层的树，当前分支加粗，显示领先/落后数）、标签、远端、已贮藏、子模块、子树，底部筛选器。分支右键菜单提供检出、合并、变基、推送、跟踪远程分支、重命名、删除等。
- 文件状态视图：已暂存 / 未暂存两组文件，diff 区按块显示并可暂存、取消暂存、丢弃区块，底部提交区。
- 历史视图：提交图 + 提交列表（图表、描述、提交、作者、日期），分支/标签标签着色；下方为选中提交的文件列表、提交详情和 diff。
- 操作对话框：拉取、推送、抓取、新建/删除分支、合并、贮藏，选项与 Sourcetree 一致，并显示将要执行的 git 命令。
- 命令日志：所有写操作执行的 git 命令可追溯。

底层借鉴 lazygit 的实现方式（不引入其代码）：调用系统 `git`，解析结构化输出；读写分离；写操作串行化；仓库在 gitview 之外变化时自动刷新。

这是一次彻底重写，不兼容旧的分析界面、旧 API 和旧数据。

## User Stories

### 启动与仓库

1. 作为用户，我想运行 `gitview` 就打开当前目录所在仓库的工作台，这样不需要额外参数。
2. 作为用户，我想运行 `gitview <路径>` 打开指定仓库，这样可以管理任意本地仓库。
3. 作为用户，我想在路径不是 Git 仓库时得到明确的错误提示和修复建议，这样知道该怎么做。
4. 作为用户，我想在本机 git 版本过低时得到明确提示（含最低版本），这样不会遇到莫名其妙的失败。
5. 作为用户，我想在标题栏看到仓库名，这样知道正在操作哪个仓库。
6. 作为用户，我想工作台只监听本机回环地址并要求会话 token，这样其他网页无法借我的浏览器改写本地仓库。
   - 2026-11-12 更新：应用户要求（单用户、本机使用）取消会话 token；保留回环监听与 `Host`/`Origin` 校验，其他网页仍无法驱动 API。见 ADR-0001 §7。
7. 作为用户，我想打开空仓库（还没有任何提交）时工作台仍然可用，这样可以完成第一次提交。

### 文件状态

8. 作为用户，我想在文件状态视图看到已暂存和未暂存的文件，这样清楚下一次提交会包含什么。
9. 作为用户，我想看到每个文件的状态图标（新增、修改、删除、重命名、未跟踪），这样一眼看出改动类型。
10. 作为用户，我想勾选单个文件把它暂存或取消暂存，这样逐个挑选要提交的内容。
11. 作为用户，我想用分组标题的勾选框一次暂存或取消暂存全部文件，这样处理大量改动更快。
12. 作为用户，我想选中一个文件后看到它的 diff（已暂存的看暂存区与 HEAD 的差异，未暂存的看工作区与暂存区的差异），这样确认改动内容。
13. 作为用户，我想看到未跟踪文件的完整内容作为新增 diff，这样新文件也能检查。
14. 作为用户，我想在 diff 中按块（hunk）暂存，这样同一个文件可以只提交部分改动。
15. 作为用户，我想在已暂存文件的 diff 中按块取消暂存，这样撤回误暂存的部分。
16. 作为用户，我想按块丢弃未暂存的改动，并在丢弃前确认，这样不会误删工作。
17. 作为用户，我想看到 diff 的块头“块 N： 行 a-b”和旧/新行号，这样定位改动位置。
18. 作为用户，我想在 diff 区搜索文本，这样快速找到关心的行。
19. 作为用户，我想过长的文件路径省略前缀并能悬停看到完整路径，这样列表不会被撑乱。
20. 作为用户，我想文件名包含空格、中文或特殊字符时也能正确显示和操作，这样不会因为文件名出错。

### 提交

21. 作为用户，我想在提交区看到当前的提交身份（`user.name <user.email>`），这样确认用哪个身份提交。
22. 作为用户，我想输入多行提交信息并提交已暂存的改动，这样完成一次提交。
23. 作为用户，我想在没有已暂存文件或信息为空时提交按钮不可用，这样避免空提交。
24. 作为用户，我想勾选“更正上一次提交”来 amend，这样修正刚才的提交。
25. 作为用户，我想勾选“立即推送变更到 origin/<分支>”在提交后自动推送，这样少一步操作。
26. 作为用户，我想提交时仓库的 hooks 照常执行，并在 hook 失败时看到它的输出，这样行为与命令行一致。
27. 作为用户，我想在提交选项里选择跳过 hooks，这样临时提交 WIP 不被拦住。
28. 作为用户，我想点标题栏的“提交”按钮直接进入文件状态视图，这样从任何地方都能开始提交。
29. 作为用户，我想“提交”按钮上显示待提交文件数，这样知道还有多少改动。

### 历史与提交图

30. 作为用户，我想在历史视图看到提交列表，列为图表、描述、提交（10 位哈希）、作者（含邮箱）、日期，这样快速浏览历史。
31. 作为用户，我想看到带颜色泳道的提交图，分叉与合并清晰可辨，这样理解分支关系。
32. 作为用户，我想当前 HEAD 提交用空心圆标出、描述加粗，这样知道自己在哪。
33. 作为用户，我想工作区有改动时列表顶部出现“未提交的更改”行，这样历史和当前改动在一起看。
34. 作为用户，我想在提交描述前看到指向它的本地分支、远程分支和标签，并按泳道颜色着色，这样知道每个提交在哪些分支上。
35. 作为用户，我想过长的分支名在中间省略并可悬停看全名，这样标签不挤占描述。
36. 作为用户，我想本地分支落后上游时在标签旁看到“落后 N 个版本”，这样知道需要拉取。
37. 作为用户，我想日期显示为“今天 HH:mm”“昨天 HH:mm”或完整日期，这样更易读。
38. 作为用户，我想切换“所有分支 / 当前分支”，这样聚焦当前工作。
39. 作为用户，我想切换“显示 / 隐藏远程分支”，这样减少干扰。
40. 作为用户，我想通过“跳转到”选择分支直接定位到它的提交，这样在长历史里快速导航。
41. 作为用户，我想在几万条提交的仓库里历史视图仍然流畅滚动，这样大仓库也能用。
42. 作为用户，我想提交图在任何滚动位置都连续，不因分页截断，这样泳道始终正确。
43. 作为用户，我想在搜索视图按提交信息、作者或哈希前缀搜索提交，这样找到特定提交。

### 提交详情与 diff

44. 作为用户，我想选中提交后看到它改动的文件列表，这样知道这个提交动了哪些文件。
45. 作为用户，我想看到提交详情：主题、正文、完整哈希、父提交、作者、作者日期、提交日期、指向它的引用，这样了解提交全貌。
46. 作为用户，我想点击父提交跳转到父提交，这样沿着历史回溯。
47. 作为用户，我想选中文件后看到该提交中这个文件的 diff，这样审阅具体改动。
48. 作为用户，我想合并提交没有文件改动时看到明确说明，这样不会以为加载失败。
49. 作为用户，我想重命名的文件显示为重命名而不是删除加新增，这样改动更清楚。
50. 作为用户，我想二进制文件和超大 diff 有明确提示而不是卡住界面，这样大文件不影响使用。

### 分支

51. 作为用户，我想在侧边栏看到按 `/` 分层的本地分支树，文件夹可折叠，这样大量分支也易于管理。
52. 作为用户，我想当前分支加粗并带标记，这样一眼看到当前分支。
53. 作为用户，我想分支旁显示相对上游的领先/落后数，这样知道是否需要推送或拉取。
54. 作为用户，我想单击分支在历史中定位到它的最新提交，这样快速查看分支。
55. 作为用户，我想双击分支检出它，这样快速切换分支。
56. 作为用户，我想检出因本地改动冲突而失败时看到 git 的原因，这样知道先贮藏或提交。
57. 作为用户，我想用“分支”对话框新建分支，可选基于工作副本父节点或指定提交，并选择是否检出，这样灵活创建分支。
58. 作为用户，我想新建分支时实时校验分支名并预览完整引用名，这样避免非法名称。
59. 作为用户，我想在“分支”对话框中删除一个或多个非当前分支，这样清理分支。
60. 作为用户，我想删除未合并的分支时得到提示并可选择强制删除，这样不会误丢提交。
61. 作为用户，我想右键分支看到与 Sourcetree 一致的菜单（检出、合并至当前、变基到、拿来、推送到、跟踪远程分支、与当前对比、重命名、删除、复制分支名字），这样常用操作就在手边。
62. 作为用户，我想通过右键菜单重命名分支，这样修正分支名。
63. 作为用户，我想通过右键菜单设置分支跟踪的远程分支，这样拉取推送有默认目标。
64. 作为用户，我想在侧边栏看到远端 origin 下的远程分支树，单击可定位，这样查看远程状态。
65. 作为用户，我想在侧边栏看到标签列表，单击可定位到标签指向的提交，这样找到发布点。
66. 作为用户，我想用底部筛选器按名称过滤分支和标签，这样在大量分支中快速找到目标。

### 拉取、推送、抓取

67. 作为用户，我想在“拉取”对话框选择远程仓库和远程分支，看到将拉取到的本地分支，这样明确拉取范围。
68. 作为用户，我想在拉取时选择：立即提交合并的改动、包括被合并提交的信息、总是创建合并提交、用变基代替合并，这样控制整合方式。
69. 作为用户，我想在“推送”对话框选择要推送的本地分支（含全选）、对应的远程分支，以及是否建立跟踪，这样一次推送多个分支。
70. 作为用户，我想选择推送所有标签，这样发布标签。
71. 作为用户，我想在“抓取”对话框选择抓取所有远端、修剪已删除的跟踪分支、抓取所有标签，这样同步远程状态而不改本地分支。
72. 作为用户，我想拉取、推送、抓取以后台任务运行并显示进度，可以取消，这样网络慢时界面不卡。
73. 作为用户，我想远程需要用户名、密码或 SSH 密钥口令时在浏览器里弹窗输入，这样不会卡在看不见的终端提示。
74. 作为用户，我想凭据不被记录到命令日志或磁盘，这样不泄露密码。
75. 作为用户，我想推送被拒绝（例如远程有新提交）时看到 git 的原因和建议（先拉取），这样知道如何处理。
76. 作为用户，我想“拉取”“推送”按钮上显示落后/领先数，这样不用打开对话框就知道同步状态。

### 合并

77. 作为用户，我想在“合并”对话框选择要合并到当前分支的分支，并选择是否立即提交、是否包含被合并提交信息、是否总是创建合并提交，这样控制合并方式。
78. 作为用户，我想通过分支右键菜单“合并 X 至当前分支”快速合并，这样少开对话框。
79. 作为用户，我想合并出现冲突时工作台明确显示仓库处于“合并中”，冲突文件被标出，并提供“中止合并”，这样知道当前状态并能退出。

### 贮藏

80. 作为用户，我想在“贮藏”对话框输入可选的信息，并选择是否保留已暂存的变更，这样把工作区恢复到干净状态。
81. 作为用户，我想在工作区没有改动时贮藏按钮不可确认并有提示，这样避免空贮藏。
82. 作为用户，我想在侧边栏“已贮藏”中看到贮藏列表，这样知道存了什么。
83. 作为用户，我想选中一个贮藏查看它包含的文件和 diff，这样决定是否恢复。
84. 作为用户，我想应用或删除一个贮藏，这样恢复或清理暂存的工作。

### 实时性与可追溯

85. 作为用户，我想在终端或编辑器里改动仓库后，工作台在几秒内自动刷新，这样界面始终是最新状态。
86. 作为用户，我想 gitview 自己执行写操作期间不出现中间状态闪烁，这样界面稳定。
87. 作为用户，我想两个写操作不会同时执行（例如连续点击），这样不会撞上 `index.lock`。
88. 作为用户，我想偶发的 `index.lock` 冲突被自动重试，这样不被其他工具的短暂锁打断。
89. 作为用户，我想在底部命令日志看到最近执行的 git 命令，这样知道工作台实际做了什么。
90. 作为用户，我想每个操作对话框显示将要执行的 git 命令预览，这样在确认前就知道效果。
91. 作为用户，我想所有失败都给出 git 的原始错误信息和可操作的建议，这样能自己排查。

### 界面

92. 作为用户，我想各面板之间的分隔可以拖动调整大小，这样适配不同屏幕。
93. 作为用户，我想界面支持浅色和深色主题（跟随系统），这样长时间使用不刺眼。
94. 作为用户，我想界面文案为中文，这样与我使用的 Sourcetree 中文版一致。

## Implementation Decisions

### 总体

- 彻底重写：删除旧的分析模块（overview、function、Tree-sitter 函数分析）、旧 API 路由和旧前端页面；不做兼容。原型路由在正式界面落地后删除。
- 继续采用“系统 `git` CLI + 结构化输出解析”的数据获取方式（ADR-0001）；不引入 lazygit 代码，也不引入 go-git。
- 本 spec 只做单仓库；URL 仍按 ADR-0001 设计为 `/api/v1/repos/{repoId}/...`，首批只有一个 repoId，为多仓库标签页留好路径。

### 后端模块（ADR-0001 分层）

- **git 执行层**：Runner 接口 + argv builder。统一注入 `LC_ALL=C`、`GIT_TERMINAL_PROMPT=0`；读命令额外 `GIT_OPTIONAL_LOCKS=0`。统一记录 argv、耗时、退出码；写命令进入命令日志。错误分类为可判别类型（非仓库、锁冲突、认证失败、冲突、引用不存在、hook 失败、被拒绝推送等）。`index.lock` 错误按退避重试。启动时检测 git 版本，低于最低版本报错。
- **repo/query（只读）**：
  - 仓库概况：名称、当前分支、HEAD、是否空仓库、进行中状态（clean / merging / rebasing / cherry-picking / reverting）、提交身份。
  - 工作区状态：`status --porcelain=v2 -z` 解析出已暂存、未暂存、未跟踪、冲突文件，含重命名。
  - 文件 diff：已暂存（`diff --cached`）、未暂存（`diff`）、未跟踪（`diff --no-index`）、提交中的文件（`show`/`diff <parent> <commit>`），开启重命名检测；二进制和超大 diff 返回标记而非全文。
  - 提交图：一次 `log` 取全部提交的 oid、parents、作者、邮箱、作者时间、提交时间、主题（字段用 `%x00` 分隔），可选范围为所有分支或当前分支；不分页截断。
  - 提交详情：正文、文件列表（`--name-status -z`）。
  - 引用：`for-each-ref` 一次取本地分支、远程分支、标签，含 `%(upstream)` 与 `%(upstream:track)`（领先/落后），不逐分支调用 `rev-list`。
  - 贮藏列表与单个贮藏的文件和 diff。
- **repo/ops（写）**：stage / unstage（文件级与 hunk 级，hunk 级由服务端构造 patch 后 `git apply --cached`，丢弃用 `git apply -R`）、commit（含 amend、跳过 hooks）、checkout、branch create / delete / rename / set-upstream、merge、merge --abort、pull、push、fetch、stash push / apply / drop。
- **workspace**：管理仓库实例；每个仓库一把写锁（读可并发）；写操作期间暂停变更检测，结束后统一刷新一次；仓库版本号；后台 Job（pull / push / fetch）带进度解析与取消。
- **变更检测**：`.git` 目录（`HEAD`、`refs/`、`packed-refs`、`index`、进行中状态文件）用 fsnotify；工作区不递归监听，改为页面可见时按间隔轮询 status、窗口获得焦点时立即刷新；低频 refs 快照轮询作为兜底。任一来源检测到变化即递增版本号并推送事件。
- **凭据**：`GIT_ASKPASS` / `SSH_ASKPASS` 指向 gitview 自带 helper 子命令，helper 回调本地服务，由前端弹窗收集；凭据不落盘、不进命令日志。

### HTTP API 契约

- 读：`GET /api/v1/repos/{repoId}`（概况）、`/status`、`/diff`（参数区分 staged / unstaged / untracked / commit + path + 可选 hunk 范围）、`/graph`、`/commits/{oid}`、`/refs`、`/stashes`、`/stashes/{index}`。
- 写：`POST /api/v1/repos/{repoId}/operations/{op}`，JSON 请求体；同步操作直接返回结果和执行的命令；长任务返回 `jobId`。
- 事件：`GET /api/v1/events`（SSE），推送 `{repoId, version, changed: ["refs","index","worktree","state"]}`、Job 进度、凭据请求。
- 每个写操作响应都带实际执行的 git 命令，供命令日志与对话框预览使用；对话框的命令预览由前端按同一规则生成，与后端返回一致。
- 安全：启动生成随机 token，打开的 URL 携带；所有 API 校验 token、`Host`、`Origin`；写接口只接受 `POST` + `application/json`；只监听回环地址。

### 提交图

- 后端返回全量拓扑（oid、parents、元数据、引用），前端计算泳道（与 lazygit 相同的思路：自上而下维护“等待某个 oid 的泳道”列表），用虚拟列表渲染。原型中泳道算法的数据形状如下（来自原型，作为决策记录）：

  ```ts
  type GraphNode = { oid: string; parents: string[] }
  type Segment = { fromLane: number; toLane: number; half: "top" | "bottom"; color: number }
  type GraphRow = { lane: number; color: number; segments: Segment[]; width: number }
  // layoutGraph(nodes: GraphNode[]): GraphRow[]
  ```

- “未提交的更改”作为一个父节点为 HEAD 的虚拟节点参与布局。

### 前端

- 以原型 `/prototype/workbench` 的布局和交互为准重写为正式页面，替换旧首页；数据改为调用新 API，React Query 管理请求，SSE 事件按 `changed` 精确失效对应查询。
- 原型中的内存假数据、模拟执行与 toast 仅用于原型，正式实现不保留。
- 对话框选项、文案、按钮与原型一致（原型已对照 Sourcetree 截图）。标题栏不包含“终端”按钮。
- 保留 gitview 自有的两处增强：对话框中的 git 命令预览、底部命令日志栏。

## Testing Decisions

- 好的测试只验证外部行为：给定一个真实仓库状态，调用接口，断言返回结果和仓库的实际状态（`git` 命令读出的结果），不断言内部函数调用或 argv 细节。
- **主测试切入点：HTTP API。** Go 测试在临时目录用脚本构建真实 git 仓库（提交、分支、合并、远程用本地 bare 仓库模拟），直接调用 server 的 handler，覆盖全部读接口与写接口。不 mock git。网络相关操作（pull / push / fetch）用本地 bare 仓库作为 origin；凭据流程用 helper 回调的接口测试。
- **前端纯逻辑：vitest。** 提交图泳道布局（分叉、合并、多父提交、虚拟“未提交的更改”节点、泳道复用）、diff 解析（块头、行号、新增/删除文件、无换行结尾）、分支树构建、日期格式化、命令预览生成。现有先例：`frontend/src/lib/table-sort.test.ts`。
- 界面布局和交互不做自动化测试，以浏览器中与原型对照的人工核对为准。
- 现有 Go 测试（`cmd/gitview`、`internal/*` 的测试）是构建临时仓库与调用 handler 的先例，随旧模块删除时保留可复用的测试辅助。

## Out of Scope

- 多仓库标签页与书签（URL 已预留）。
- 交互式 rebase、cherry-pick、revert、按行（而非按块）暂存、reflog 撤销、冲突逐块解决界面（本 spec 只做冲突状态展示与中止合并）。
- 子模块、子树、标签的创建与删除（只读展示）。
- 显示远程服务器、在 Finder 中显示、设置三个按钮的功能（占位）。
- 终端功能（明确不做）。
- 拉取请求创建、托管平台集成（GitHub / GitLab / Gitee）。
- 旧分析功能（贡献者、热点、所有权、函数历史）。
- 桌面应用打包（Wails / Tauri）。
- 英文界面。
